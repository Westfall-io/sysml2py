# sysml2py (generated)

Version **1.0.0** — generated by **sysml2py-lab** from the SysML v2
grammar + relationship model + corpus (issues #6/#7/#8/#9/#13).

Capabilities:
- Generated AST node classes per grammar rule
- Membership-dispatch table from children.json
- `dump()` / `get_definition()` on every node (loss-minimizing)
- `Unsupported` nodes carry raw text (zero NotImplementedError)
- Compiled grammar shipped as package data; provenance in
  `sysml2py.provenance`

## Building a model (friendly builder API)

Friendly names drop the `Builder`/`Usage`/`Definition` suffixes —
`Part`, `Attribute`, `Item`, ... are builders; usage vs definition is
chosen at creation via `kind=`; `add()` appends children so a full
package dumps from nested composition:

```python
from sysml2py import PackageBuilder, Part, Attribute

pkg = PackageBuilder('MyModel')
stage = Part('Stage_1')
stage.add(Attribute('mass'))
stage.add(Attribute('thrust'))
pkg.add(stage)
print(pkg.dump())
```

```
package MyModel {
  part Stage_1 {
    attribute mass;
    attribute thrust;
  }
}
```

Definitions are the same class with `kind=` at creation:
`Part('Stage_1', kind='definition')` -> `part def Stage_1;`

Kinds without a definition form (`Package`, `Comment`, `Actor`,
`Reference`, `Transition`, `Import`, `Message`, `Succession`,
`AliasMember`, `Subject`, `ObjectiveRequirement`) reject
`kind='definition'` with a `ValueError` — the generator never
emits a definition it cannot cast back (and a class-name kind
like `'PartDefinition'` raises
too, since that would print invalid SysML).

`Package`/`Comment`/`Import`/`Message`/`Succession`/`AliasMember`
keep the `*Builder` suffix
(their friendly names are the AST node classes). The classic `*Builder`
names (`PartUsageBuilder`, ...) remain available.

Value-bearing attributes are supported: `Attribute('mass', value=1000,
unit='kg')` renders `attribute mass = 1000[kg];`, with the unit imported
automatically as `public import SI::kg;` (issue #26, lab repo). You may also
pass an astropy `Quantity` and the unit is derived from it (`value=1000*u.kg`)
— add `import astropy.units as u` yourself, since the runtime stays
pure-stdlib (astropy is not bundled; see the migration note).
